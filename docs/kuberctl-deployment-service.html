Troubleshooting Minikube Service Access and Common kubectl Commands

1. Applying Kubernetes Resources

To apply a resource, you must specify the file:

kubectl apply -f <filename>
Example:
kubectl apply -f spring-hello-service.yaml

2. Checking Services and Pods

  • List all services: kubectl get svc
  • List all pods: kubectl get pods
  • List both services and pods: kubectl get svc,pods

3. Deleting Resources

  • Delete a service: kubectl delete service <service-name>
  • Delete a deployment: kubectl delete deployment <deployment-name>

4. Exposing Services

To expose a service outside the cluster, use type: NodePort or type: LoadBalancer in your service YAML.

Example NodePort service YAML: 
{
  apiVersion: "v1",
  kind: "Service",
  metadata: {
    name: "springboot-k8s-svc"
  },
  spec: {
    selector: {
      app: "spring-boot-k8s"
    },
    ports: [
      {
        protocol: "TCP",
        port: 8080,
        targetPort: 8080
      }
    ],
    type: "NodePort"
  }
}

5. Finding Service Access Information

  1. After applying your service, check the assigned NodePort:
    kubectl get svc
  2. Get the Minikube IP:
    minikube ip
  3. Access your service:
    curl http://<minikube-ip>:<NodePort>/hello?name=sarvesh

6. Common Issues and Solutions

a. Cannot Access Minikube IP

  • Minikube with Docker driver on macOS isolates the VM from your host network.
  • ICMP (ping) is often blocked; use curl for HTTP checks.
  • Use minikube service <service-name> to open a tunnel and access your service locally.
    minikube service spring-hello-svc |-----------|------------------|-------------|---------------------------| | NAMESPACE | NAME | TARGET PORT | URL | |-----------|------------------|-------------|---------------------------| | default | spring-hello-svc | 8080 | http://192.168.49.2:30154 | |-----------|------------------|-------------|---------------------------| 🏃 Starting tunnel for service spring-hello-svc. |-----------|------------------|-------------|------------------------| | NAMESPACE | NAME | TARGET PORT | URL | |-----------|------------------|-------------|------------------------| | default | spring-hello-svc | | http://127.0.0.1:49660 | |-----------|------------------|-------------|------------------------|
    🎉 Opening service default/spring-hello-svc in default browser... ❗ Because you are using a Docker driver on darwin, the terminal needs to be open to run it

b. Firewall Issues

  • Check firewall status (macOS): sudo /usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
  • Ensure Docker and Minikube traffic is allowed if firewall is enabled.

c. Service Not Responding

  • Ensure your app listens on 0.0.0.0 (not just localhost).
  • Check pod and service status: kubectl get pods, kubectl get svc
  • Check logs: kubectl logs <pod-name>

7. Using minikube service

  • Recommended for Docker driver on macOS: minikube service <service-name>
  • Starts a tunnel and opens the service in your browser.
  • Provides a localhost URL for access.
  • Keep the terminal open while the tunnel is running.

8. Working with Deployments

  • Apply a deployment YAML file: kubectl apply -f <deployment-file>.yaml
  • List all deployments: kubectl get deployments
  • Delete a deployment: kubectl delete deployment <deployment-name>
  • Check deployment status: kubectl rollout status deployment/<deployment-name>
  • View deployment details: kubectl describe deployment <deployment-name>

Summary: When using Minikube with the Docker driver on macOS, direct access to the Minikube IP may not work due to network isolation. Always use minikube service <service-name> to access your services. Ensure your YAMLs are correct and your app listens on all interfaces.
